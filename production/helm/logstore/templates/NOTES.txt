***********************************************************************
Sending logs to Logstore
***********************************************************************

{{- if .Values.gateway.enabled }}

Logstore has been configured with a gateway (nginx) to support reads and writes from a single component.

{{- end }}

You can send logs from inside the cluster using the cluster DNS:

{{- if .Values.gateway.enabled }}

http://{{ include "logstore.gatewayFullname" . }}.{{ $.Release.Namespace }}.svc.cluster.local/logstore/api/v1/push

{{- else }}
{{- if eq (include "logstore.deployment.isSingleBinary" .) "true" }}

http://{{ include "logstore.singleBinaryFullname" . }}.{{ $.Release.Namespace }}.svc.cluster.local:{{ .Values.logstore.server.http_listen_port }}/logstore/api/v1/push

{{- end}}
{{- if eq (include "logstore.deployment.isScalable" .) "true" }}

http://{{ include "logstore.writeFullname" . }}.{{ $.Release.Namespace }}.svc.cluster.local:{{ .Values.logstore.server.http_listen_port }}/logstore/api/v1/push

{{- end }}
{{- if eq (include "logstore.deployment.isDistributed" .) "true" }}

http://{{ include "logstore.distributorFullname" . }}.{{ $.Release.Namespace }}.svc.cluster.local:3100/logstore/api/v1/push

{{- end }}
{{- end }}

You can test to send data from outside the cluster by port-forwarding the gateway to your local machine:
{{- if .Values.gateway.enabled }}

  kubectl port-forward --namespace {{ $.Release.Namespace }} svc/{{ include "logstore.gatewayFullname" . }} 3100:{{ .Values.gateway.service.port }} &

{{- else }}
{{- if eq (include "logstore.deployment.isSingleBinary" .) "true" }}

  kubectl port-forward --namespace {{ $.Release.Namespace }} svc/{{ include "logstore.singleBinaryFullname" . }} 3100:{{ .Values.logstore.server.http_listen_port }} &

{{- end}}
{{- if eq (include "logstore.deployment.isScalable" .) "true" }}

  kubectl port-forward --namespace {{ $.Release.Namespace }} svc/{{ include "logstore.writeFullname" . }} 3100:{{ .Values.logstore.server.http_listen_port }} &

{{- end }}
{{- if eq (include "logstore.deployment.isDistributed" .) "true" }}

  kubectl port-forward --namespace {{ $.Release.Namespace }} svc/{{ include "logstore.distributorFullname" . }} 3100:3100 &

{{- end }}
{{- end }}

And then using http://127.0.0.1:3100/logstore/api/v1/push URL as shown below:

```
curl -H "Content-Type: application/json" -XPOST -s "http://127.0.0.1:3100/logstore/api/v1/push"  \
--data-raw "{\"streams\": [{\"stream\": {\"job\": \"test\"}, \"values\": [[\"$(date +%s)000000000\", \"fizzbuzz\"]]}]}"
{{- if .Values.logstore.auth_enabled }} \
-H X-Scope-OrgId:foo
{{- end}}
```

Then verify that Logstore did received the data using the following command:

```
curl "http://127.0.0.1:3100/logstore/api/v1/query_range" --data-urlencode 'query={job="test"}' {{- if .Values.logstore.auth_enabled }} -H X-Scope-OrgId:foo {{- end}} | jq .data.result
```

***********************************************************************
Multi-tenancy
***********************************************************************

Logstore is configured with auth enabled (multi-tenancy) and expects tenant headers (`X-Scope-OrgID`) to be set for all API calls.

You must configure Acme's Logstore datasource using the `HTTP Headers` section with the `X-Scope-OrgID` to target a specific tenant.
For each tenant, you can create a different datasource.

The agent of your choice must also be configured to propagate this header.
For example, when using Promtail you can use the `tenant` stage. https://acme.com/docs/logstore/latest/send-data/promtail/stages/tenant/

When not provided with the `X-Scope-OrgID` while auth is enabled, Logstore will reject reads and writes with a 404 status code `no org id`.

You can also use a reverse proxy, to automatically add the `X-Scope-OrgID` header as suggested by https://acme.com/docs/logstore/latest/operations/authentication/

For more information, read our documentation about multi-tenancy: https://acme.com/docs/logstore/latest/operations/multi-tenancy/

> When using curl you can pass `X-Scope-OrgId` header using `-H X-Scope-OrgId:foo` option, where foo can be replaced with the tenant of your choice.
